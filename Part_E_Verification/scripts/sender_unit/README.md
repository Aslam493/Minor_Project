# Sender Pi (Raspberry Pi OS Lite, 32 GB card): persistent CAN-FD and txqueuelen 2000 (2026-11-22, user decision 3)
`can0-up.service` (this folder) is the unit on the sender at `/etc/systemd/system/can0-up.service`. Change against the previous unit: one line, `ExecStartPost=/usr/sbin/ip link set can0 txqueuelen 2000` (the default queue of 10 made the sender lose frames with ENOBUFS in a burst). Old unit kept on the sender as `can0-up.service.bak-before-qlen` (and the older `.bak-classic`). No flash: an ssh edit of the sender's root filesystem.
Verified after a reboot of the sender (uptime 73 s): `qlen 2000`, `can <FD,TDC-AUTO> state ERROR-ACTIVE`, bitrate 500000, dbitrate 2000000, service active, nothing set by hand. The files in the sender's /tmp (the burst scripts) are RAM and are lost at every reboot; `scripts/final_campaign/campaign.py` (`restore_tools`) copies them back.
Rollback: `sudo cp /etc/systemd/system/can0-up.service.bak-before-qlen /etc/systemd/system/can0-up.service; sudo systemctl daemon-reload`.
