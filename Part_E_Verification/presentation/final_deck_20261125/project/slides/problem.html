MOTIVATION AND PROBLEM

CAN trusts every frame, and Linux can lie about it

Nothing on CAN checks who sent a frame. Three trust questions follow:

1 · THE MESSAGE

Can we trust the frame?

2 · THE DECISION

Can we trust the check made on it?

3 · THE RECORD · FUTURE WORK

Can we trust the log later?

Spoofed ID

Any node can send any ID

Tampered data

Payload changed on the way

Replayed frame

An old valid frame sent again

Silence

Frames or checks quietly stopped

Goal: detect all four attacks from OP-TEE Secure World, a part of the processor kept apart from Linux, so questions 1 and 2 stay answered even if Linux is compromised.

Secure CAN Monitor · Raspberry Pi 3 · OP-TEE

Three trust questions, from the midterm: the message, the decision, and the record. This work answers the first two. The third, a log Linux cannot rewrite, is designed but not built, and is the first item of future work. Four ways a CAN stream can be attacked. A checker running in Linux cannot be trusted if Linux itself is compromised: it could hide any of these. So the goal is to judge frames from Secure World, a place Linux cannot change.
