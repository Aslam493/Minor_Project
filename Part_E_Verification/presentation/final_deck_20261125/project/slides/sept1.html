Secure CAN Monitor · Raspberry Pi 3 · OP-TEE

Previous work, part 1, from 23 August to 8 September. I built the secure platform by hand: OP-TEE, TF-A, U-Boot, the Linux kernel and the root file system for the Raspberry Pi 3, in ten steps, and booted it on the real board. The key change is in BL31, the secure monitor at EL3: when Linux brings up CPU1, the request is intercepted and the core is sent into Secure World, where it runs the monitor loop forever. Linux keeps CPU0, 2 and 3. Evidence: OP-TEE answers from Linux, xtest ran 114 test cases and 36,114 subtests with 0 failed, and my own Trusted App completed a challenge and response round trip. This is still how the final system works.
