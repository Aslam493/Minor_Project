Secure CAN Monitor · Raspberry Pi 3 · OP-TEE

Final design. Linux on cores 0, 2 and 3 owns the CAN chip and carries frames; the monitor in Secure World on core 1 judges them and keeps no frames. The design changed twice after midterm. Reading the chip from Secure World gave no real protection, because the Pi 3 has no TZPC to lock SPI0. Letting Linux push frames gave Linux control of the timing. Now Secure World opens a numbered request every 50 ms, the dashed loop, and Linux must answer within 40 ms with up to 32 frames, so a late or missing answer becomes evidence.
